# Go Language Rules

- Go is the only application language. Do not introduce Node.js, npm, or a
  JS/TS build step for anything user-facing.
- Code must be `gofmt`-clean and pass `go vet ./...`.
- Prefer the standard library over new dependencies. Justify every new
  dependency in the commit message (what it replaces, why stdlib/existing
  deps are insufficient).
- Avoid `interface{}`/`any` and reflection unless there is no reasonably
  simple typed alternative.
- Exported identifiers under `pkg/*` are public API — see
  `.agents/rules/02-architecture.md` for the stability rule.
- Errors are values: wrap with context (`fmt.Errorf("...: %w", err)`), never
  swallow an error silently.
- Concurrency: any goroutine you start must have a clear owner and shutdown
  path (no goroutine leaks); guard shared state (`pkg/ws`, `pkg/store`) with
  appropriate synchronization and cover it with `go test -race`.
